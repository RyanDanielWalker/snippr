Snippr 1.2.1 is housekeeping. Nothing on screen changed. It clears the last advisories from a full `npm audit`, settles which version of Node Snippr runs on, and moves the tests to Vitest 5. Try it at [snippr.dev](https://snippr.dev). The demo needs no account.

## Underneath

- **A full `npm audit` comes back empty.** 1.2 cleared the packages that ship to the live site. The tools that only run on a developer's machine or in CI still had two advisories. `minimatch`, under the TypeScript lint rules, moved to its fixed release once `typescript-eslint` 8.73 accepted it. GitHub withdrew the `picomatch` advisory, so that one needed no change. ([0063](https://github.com/RyanDanielWalker/snippr/blob/v1.2.1/docs/adr/0063-close-1-2-and-scope-1-2-1-to-dependency-housekeeping.md), [0042](https://github.com/RyanDanielWalker/snippr/blob/v1.2.1/docs/adr/0042-leave-the-minimatch-alert-open-until-lint-tools-can-take-the-fix.md))
- **Snippr runs on Node 24 everywhere.** Before, CI used Node 22, Vercel used whatever its dashboard said, and nothing in the repo said which was right. Now `package.json` names Node 24 once, and Vercel, CI, and the local version manager all read it from there. ([0064](https://github.com/RyanDanielWalker/snippr/blob/v1.2.1/docs/adr/0064-run-on-node-24-named-once-in-package-json-engines.md))
- **The tests run on Vitest 5.** The 678 unit tests and 50 database tests passed without changes. Vitest 5 is stricter in one way that matters here: a test that forgets to `await` an async check now fails, where Vitest 4 let it pass with a warning.
- **The MCP server reports version `1.2.1`.**

The full list is in the [roadmap](https://github.com/RyanDanielWalker/snippr/blob/v1.2.1/docs/ROADMAP.md), and every decision has a record in [`docs/adr/`](https://github.com/RyanDanielWalker/snippr/tree/v1.2.1/docs/adr).

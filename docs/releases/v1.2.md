Snippr 1.2 adds an archive, tidies the sidebar, and closes three security gaps a reader of the code would likely find. Try it at [snippr.dev](https://snippr.dev). The demo needs no account.

## What you'll notice

- **An archive.** A finished snippet can leave your library without being deleted. Archive it from its card or the preview, and it drops out of your library, its folder, and search. An Archive row appears in the sidebar while anything is in it. Unarchive puts the snippet back in the folder it came from. Archived snippets still count toward the 50-snippet limit, and AI search leaves them out, in the app and over MCP. ([0056](https://github.com/RyanDanielWalker/snippr/blob/v1.2/docs/adr/0056-archive-snippets-with-an-archivedat-column.md))
- **Cards say when they were made.** "Nov 16" on the card, with the year when it isn't this one, and "Created Nov 16" in the preview. The day is in your time zone.
- **A tidier sidebar.** Library is the panel's title, with All snippets, Unorganized, and Archive under it and Folders indented beneath. Every row has an icon, and a new folder is the + on the Folders heading. ([0058](https://github.com/RyanDanielWalker/snippr/blob/v1.2/docs/adr/0058-group-the-archive-with-the-library-and-give-sidebar-rows-icons.md))
- **Collapsing the sidebar leaves a rail of icons.** It used to shrink to a small box with an arrow. Now it narrows to one square per row: icons for the library rows, a first letter for each folder. You can still click them, and still drag a card onto a folder. ([0059](https://github.com/RyanDanielWalker/snippr/blob/v1.2/docs/adr/0059-collapse-the-sidebar-to-an-icon-rail.md))

## Fixed

- **Generate works on saved prompts that list steps.** Claude's descriptions of them ran a few words over the limit, so Snippr's own check threw them away. Claude is now asked what the prompt is for, not what each step does. The check is unchanged. ([0055](https://github.com/RyanDanielWalker/snippr/blob/v1.2/docs/adr/0055-ask-for-a-saved-prompts-goal-not-its-steps.md))
- **A card without a description no longer has a gap in the middle.** The code box grows into the spare height, so it shows more code instead.

## Underneath

- **Sign-in sessions are stored as a hash.** The database used to keep each session's token exactly as your browser's cookie holds it, so a leaked row would work as a cookie. It now keeps the token's SHA-256, a one-way fingerprint: Snippr can check a cookie against it, but the fingerprint can't be turned back into the cookie. Everyone was signed out once when this went out, and any demo in progress ended. ([0061](https://github.com/RyanDanielWalker/snippr/blob/v1.2/docs/adr/0061-store-session-tokens-as-their-sha-256.md), [0052](https://github.com/RyanDanielWalker/snippr/blob/v1.2/docs/adr/0052-sign-everyone-out-once-when-session-tokens-are-hashed.md))
- **The database refuses two users whose emails differ only in capital letters.** The app already lowercases emails before saving them. This is the backstop for any code that forgets. ([0060](https://github.com/RyanDanielWalker/snippr/blob/v1.2/docs/adr/0060-refuse-case-only-duplicate-emails-with-a-unique-index-on-lower-email.md))
- **Sign-in accounts linked before the verified-email check were audited.** Every link was checked by hand, and none looked wrong. ([audit](https://github.com/RyanDanielWalker/snippr/blob/v1.2/docs/audits/2026-11-12-account-links.md))
- **`npm audit` is clean for production packages again.** Next.js moved to 16.4.6, and two packages the MCP server uses moved to fixed releases. ([0062](https://github.com/RyanDanielWalker/snippr/blob/v1.2/docs/adr/0062-clear-the-production-audit-before-tagging-1-2.md))
- **The MCP server reports version `1.2.0`.**

Small: `useDialogFocus` and a role on the drawer wrapper. New.

Small: a sentence in the doc, or a higher limit for the e2e build. New.
4. **Two stale dates.** `docs/ARCHITECTURE.md:5` says "Last reviewed: 2026-10-22 (after ADR 0029)" but describes 0030 and 0031. `docs/ROADMAP.md:3` says 2026-10-22 but lists work done 2026-10-23. Small. New.

## Can Ryan answer for it?

Since the last audit: 15 commits over Oct 22 to 23, all co-authored with Claude (6 `fix:`, 5 `docs:`, 2 `feat:`, 1 `test:`, 1 `chore:`). Whole history: 193 of 225 co-authored.

1. **"How do the three caps stay true under parallel requests?"** (`src/lib/create-lock.ts:20-30`, [0025](../adr/0025-serialize-snippet-creates-per-user-with-an-advisory-lock.md)) Each capped create runs its count and insert in one transaction that first takes `pg_advisory_xact_lock` on a hash of the kind and user id, so a second create waits and then counts the first one's row. The prefix keeps folder creates from waiting on snippet ones, and the cost is a pooled connection held while it waits.
2. **"Why `inert` instead of a focus-trap library or a portal?"** (`src/lib/dialog-focus.ts:50`) `inert` takes an element out of the tab order and the screen reader's view at once, so it does what a keydown trap does and covers screen readers too. Marking siblings while walking up from the dialog leaves it where React rendered it, and live regions are skipped so toasts still announce.
3. **"Why restore the page before focus, and why check `isConnected`?"** (`src/components/useDialogFocus.ts:28-32`, `src/lib/dialog-focus.ts:16-24`) Focusing something inside an inert element does nothing, so the page comes back first. After a delete from the preview the card that opened it is gone, so focus only returns if the opener is still on the page.
4. **"How do you test focus code in a Node test runner?"** (`src/lib/dialog-focus.ts`, `e2e/demo.spec.ts`) The functions take small interfaces (`Focusable`, `InertTarget`) instead of DOM elements, so unit tests pass fakes. The end-to-end test then tabs past the end of both dialogs in real Chromium and fails if focus lands behind them.
5. **"Why no full Content Security Policy?"** ([0031](../adr/0031-send-security-headers-without-a-full-csp.md)) Next puts inline scripts in every page, so a real policy needs `'unsafe-inline'`, which allows the attack it exists to stop, or a per-request nonce from a proxy. The only user content is your own, escaped by Shiki and React, so it sends the headers that cost nothing, including `frame-ancestors 'none'` against clickjacking, and names when to revisit.
6. **"Why is the collapsed sidebar a cookie and not `localStorage`?"** (`src/lib/sidebar.ts`, `src/app/dashboard/page.tsx:35-37`) `localStorage` only exists in the browser, so the server drew the sidebar open and it snapped shut once the JavaScript ran. A cookie comes with the request, so the server draws it collapsed from the first frame, at no extra cost since the dashboard renders per request for the session anyway.

Clever without an explanation: the nested `startTransition` is still the only one. Everything new this round has its reason next to it.

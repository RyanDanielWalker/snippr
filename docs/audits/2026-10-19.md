## Findings

Ranked by how much each matters to "an engineer clicks the link and reads the code."

1. **The README promises things the app doesn't do.** "Fully responsive: works on mobile and desktop" (`README.md:31`), but the sidebar is always `w-56` beside the content (`src/components/FolderSidebar.tsx:179`, `src/components/DashboardClient.tsx:250`). At 375px that leaves about 70px for a search row with about 235px of fixed-width buttons, so the page scrolls sideways. Also: the clone URL is `YOUR_USERNAME` (`README.md:70`), it calls Google OAuth required where DEVELOPMENT.md says optional, and the project structure (`README.md:113-133`) lists 2 of about 30 lib files and no tests, scripts, or CI. Small now (drop the claim, fix the URL, link to the ARCHITECTURE code map); the mobile pass itself is medium. Mobile pass and README rebuild are on the roadmap (Phases 3 and 5); the false claim and stale map are new.
2. **AI search results go stale after any change.** `aiResults` holds copies of snippets (`src/components/DashboardClient.tsx:52, 119, 168`) that `router.refresh()` never updates. Run an AI search, delete a result: the card stays, stuck on "Deleting..." (`src/components/SnippetCard.tsx:69` never resets `deleting` on success). Edit that card: "Snippet not found." Edit a result: the old title stays until you search again. Small (keep ids, look them up in `snippets`). New.
3. **No indexes on foreign keys.** `Snippet.userId`, `Folder.userId`, `Snippet.folderId`, `Session.userId`, `Account.userId` (`prisma/schema.prisma:28-50`; `prisma/migrations/0_init` only indexes uniques), and Postgres doesn't add them on its own. Every dashboard load filters by `userId`, demo cleanup cascades through these tables, and deleting a folder scans every snippet to null out `folderId`. Invisible at today's size, but an engineer reading the schema will ask. Small (one additive migration). New.
4. **Updates and deletes target a bare id.** `src/lib/library-store.ts:27, 30, 48, 51` use `where: { id }` after a separate ownership check. Safe today because owners never change, but `CLAUDE.md` says every query is scoped by `userId`, and the MCP server will add new callers. `where: { id, userId }` works in Prisma 5 and makes the database enforce it too. Small. New.
5. **ARCHITECTURE.md has drifted.** "Last reviewed: 2026-10-18 (after ADR 0013)" (line 5) while it documents through 0020. The code map leaves out `scripts/deploy-migrations.mjs`, `scripts/migrate-gate.mjs` (the core of ADR 0016), and `prisma/migrations/`. `src/lib/library-store.ts:8` says "Not unit-tested" while ARCHITECTURE and `library-store.db.test.ts` say it is. ROADMAP Phase 2 is all ticked but still sits under 1.0 with one-time production instructions, one naming `npm run db:push`, which no longer exists. Small. New.
6. **The two snippet modals and their types are copies.** `NewSnippetModal.tsx` and `EditSnippetModal.tsx` share about 200 near-identical lines; `type Snippet` is defined four times (`DashboardClient.tsx:22`, `SnippetCard.tsx:12`, `SnippetModal.tsx:6`, `EditSnippetModal.tsx:8`) and `Folder` four times. A new field means editing two to four files. Medium. New. Best done with Phase 3, since those files get restyled anyway.
7. **The AI rate-limit SQL never runs in a test.** Unit tests fake `incrementAiUsage` (`src/lib/ai-usage.ts:15-21`), and the end-to-end test skips AI. A typo in a quoted column would surface only as 500s on AI calls in production. The demo's matching SQL at least runs in the e2e test. Small. Partly on the roadmap: the Phase 4 AI tests use fakes and wouldn't catch this.
8. **Folder create can run twice.** Press Enter, click away while the request is in flight, and `handleCreate` runs again (`src/components/FolderSidebar.tsx:98-110, 304-306`): two folders. Small. Extends the Parked "blur saves too" item.
9. **Some client failures are silent.** `codeToHtml(...).then(setHtml)` has no catch (`src/components/SnippetModal.tsx:30-33`), so a failed Shiki load leaves a blank preview and an unhandled rejection. Clipboard writes aren't awaited and say "Copied" even when they fail (`SnippetCard.tsx:57`, `SnippetModal.tsx:45`). Small. New.
10. **Two code styles, no formatter.** `src/lib/auth.ts`, `src/lib/prisma.ts`, `src/app/api/snippets/search/route.ts`, `src/app/dashboard/page.tsx`, and `src/app/login/page.tsx` leave out semicolons; everything else uses them. Small (Prettier, one `style:` commit). New.
11. **Worth knowing, no fix needed.** `src/app/dashboard/page.tsx:14-26` repeats the store queries instead of calling `snippetStore.list` and `folderStore.list`. `GET /api/snippets` and `GET /api/folders` aren't used by the interface (the MCP server may want them). `JSON.parse(JSON.stringify(...))` at `src/app/dashboard/page.tsx:30` has no comment; React 19 can pass a `Date` to a client component directly.

Already known, not counted as new: AI handlers inline and untested, two model ids, no timeout (Phase 4); Arial overriding Geist, blank first render (Phase 3); accessibility (Parked; the modal inputs are placeholder-only too); the snippet cap race ([0013](../adr/0013-snippet-cap-of-50-for-members-and-10-for-guests.md)); prompt injection ([0005](../adr/0005-ai-features-as-synchronous-claude-calls.md), stops being theoretical with MCP); getting past the per-IP demo limit ([0012](../adr/0012-demo-mode-as-expiring-guest-users.md), Parked ceiling).

The fork is ordering:

- **A. Keep the order (design, then MCP).** Better first impression first. Risk: design polish has no natural end, and the differentiator lands late.
- **B. MCP first.** Best interview story. But phone visitors keep seeing a broken dashboard, and the security model changes before the basics are tidy.

Before MCP: the open-decisions table frames it as "local (no token) vs remote (token)," but even a local stdio server has to authenticate to snippr.dev to reach your library. Either way the API needs a second way to log in besides NextAuth cookies (personal access tokens, say), which changes the house rule "resolve the session first." That deserves its own ADR before any MCP code.

Missing from 1.0: foreign-key indexes and a formatter, both small. Nothing in 1.0 needs to leave.

## Can Ryan answer for it?

Whole history: 117 commits. April 13 to 23: 31 commits, none co-authored. October 17 to 19: 86 commits, 85 co-authored with Claude (35 `docs:`, 21 `feat:`, 11 `fix:`, 8 `chore:`, 6 `test:`, 5 `refactor:`). That is the whole security, testing, CI, demo, and migrations story.

Questions an engineer would likely ask:

1. **"How do you stop one user from touching another's data?"** (`src/lib/snippets.ts:54-57, 108-112`, `src/lib/folder-ownership.ts`, `src/lib/library-store.db.test.ts`) Every handler resolves the session, then loads the record and compares its `userId` before doing anything, including a `folderId` sent in the body. Missing and someone else's both return 403 so ids can't be probed, and the list queries are tested against real Postgres with two users.
2. **"How does AI search work, and why not embeddings?"** (`src/app/api/snippets/search/route.ts:40-66`, ADR 0005) It sends Claude the query plus a numbered list of every snippet's title, tags, and description, and Claude returns the matching numbers. That shipped in an afternoon and works because the library is capped at 50; embeddings are the version that scales, and they're parked with that reasoning.
3. **"How does the rate limiter work, and why raw SQL?"** (`src/lib/ai-usage.ts:14-23`, `src/lib/rate-limit.ts:78-90`, ADR 0011) A fixed one-hour window counted in Postgres with one `INSERT ... ON CONFLICT DO UPDATE ... RETURNING`, which is atomic, so two requests at once can't both read 29. Prisma's `upsert` can split into a read and a write, which is exactly that race.
4. **"How does the demo sign someone in without OAuth?"** (`src/app/actions/start-demo.ts`, `src/lib/guest.ts:40-63`, ADR 0012) A Server Action creates a guest user, a seeded library, and a session row in one transaction, then sets the same cookie NextAuth would. An adapter wrapper treats an expired guest's session as no session, because NextAuth keeps pushing the session's own expiry out.
5. **"How do schema changes reach production safely?"** (`scripts/deploy-migrations.mjs`, `scripts/migrate-gate.mjs`, ADR 0016, `.github/workflows/ci.yml:80-81`) Only Vercel's production build runs `prisma migrate deploy`, before `next build`, so a failed migration fails the build and the old version stays live. CI applies every migration to an empty database first, and migrations must be add-first because the old code is still serving while they run.
6. **"Why pass a store into your handler logic instead of mocking Prisma?"** (`src/lib/snippets.ts:32-42`, ADR 0018) The rules (who may do what, the cap, the order of checks) get tested against an in-memory store without knowing Prisma's call shapes. The real queries get their own tests against Postgres, because a fake can't tell when a query forgets its `userId`.
7. **"Your update uses `where: { id }`. Isn't that a gap?"** (`src/lib/library-store.ts:27`) The ownership check runs just before it and a snippet's owner never changes, so it's safe today. Putting `userId` in the `where` would make the database enforce it too, which matters once MCP adds new callers (finding 4).

Clever without an explanation: only `JSON.parse(JSON.stringify(...))` at `src/app/dashboard/page.tsx:30`.

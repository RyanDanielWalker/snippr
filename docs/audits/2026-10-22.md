## Findings

Ranked by how much each matters to "an engineer clicks the link and reads the code."

1. **The README says Claude Sonnet; the code says Haiku.** `README.md:38` lists "Claude Sonnet". `src/lib/ai.ts:17` and [0023](../adr/0023-one-ai-module-on-claude-haiku.md) say `claude-haiku-5-5`, and 0023 is the one that explains why. A visitor who reads the README then opens the ADR index sees the project contradict itself on its own differentiator. The README rebuild is on the roadmap (Phase 5), but this one line shouldn't wait for it. Small. New.
2. **The README doesn't mention the MCP server, the Connect page, or the themes.** `README.md:16-29` is the feature list from before Phase 4 and 5. The MCP server is a 1.0 criterion (`docs/ROADMAP.md:13`) and the thing that makes this more than a CRUD app, and the only README trace of it is a link to the architecture doc. On the roadmap (the README rebuild is the next Phase 5 item). Medium. Listed here because the fix is the next item and this is the reason it matters.
3. **Folder and token caps can be passed under parallel requests.** `src/lib/folders.ts:64-69` and `src/lib/api-tokens.ts:107-119` count, then insert, with no lock. Send 20 folder creates at once to an account with 45 folders and it ends past 50, the same race [0025](../adr/0025-serialize-snippet-creates-per-user-with-an-advisory-lock.md) fixed for snippets. 0025 line 52 records it as "Not done here," but the roadmap doesn't carry it, so it's a known gap with no home. `docs/ARCHITECTURE.md:101` says folders "work the same way" right after describing the lock, which a reader will take to mean they're locked too. Small to lock them the same way, or one sentence to say they aren't. From reading the code. Known in the ADR, missing from the roadmap.
4. **Focus doesn't move into dialogs, and doesn't come back.** `src/components/SnippetModal.tsx:52-58` and `SnippetFormModal.tsx:112-118` set `role="dialog"` and `aria-modal`, but nothing calls `focus()` on open or restores it on close, and Tab still reaches the cards behind the overlay. A keyboard user who opens a preview is still "on" the card they clicked. Lighthouse doesn't flag it, which is why the Phase 5 pass didn't catch it. Small (an `autoFocus` on the close button and a ref to restore). Belongs with the Parked screen-reader items; not listed there today.
5. **Two unused endpoints.** `GET /api/snippets` and `GET /api/folders` (`src/app/api/snippets/route.ts:13`, `src/app/api/folders/route.ts:13`) have no caller: `callApi` only allows POST, PATCH, and DELETE (`src/lib/api-client.ts:18`), the pages query Prisma directly, and the MCP server calls the lib functions. They're correct and tested, so this is a question to have an answer for ("they're the API's read side; the pages read through Prisma because they render on the server"), not a fix. Noted in both earlier audits. Small to delete, or leave.
6. **Worth knowing, no fix needed.**
   - `src/app/dashboard/page.tsx:17-29` repeats the two store queries instead of calling `snippetStore.list` and `folderStore.list`. Same shape, same `userId` scope, so it's duplication rather than risk.
   - `src/lib/demo.ts:9` and `src/lib/landing-samples.ts:1` import a type from `src/components/`, so `lib` depends on `components` for one type. Moving `SnippetCardData` to `library-types.ts` would make the layering one-way.
   - `src/lib/mcp.ts:98` reports version `1.0.0` to MCP clients while `package.json` says `0.1.0`. Pick one when `v1.0` is tagged.
   - The nested `startTransition` in `SnippetFormModal.tsx:77-82` and three other places still says what it does, not why React 19 needs the second wrap. Flagged last audit; unchanged.
   - `src/app/error.tsx:21` uses `unstable_retry`. That's the right prop for Next 16.4 (added in 16.2 per `node_modules/next/dist/docs/.../error.md:332`), but the name means it may change on the next upgrade.

Questions an engineer would likely ask after this round:

1. **"How does the MCP server share the API's rules instead of copying them?"** (`src/lib/mcp.ts:57-94`, [0024](../adr/0024-remote-mcp-server-with-personal-access-tokens.md)) Each tool builds a plain `Request` with its JSON body and hands it to the same function the Route Handler calls, then turns the `Response` back into a tool result. So the zod schema, the ownership check, the cap, and the rate limit run once, in one place, and the tool can't drift from the API.
2. **"Why are the tokens hashed with plain SHA-256 and not bcrypt?"** (`src/lib/api-tokens.ts:14-17, 45-51`) A password is short and guessable, so you slow the hash down; a token is 32 random bytes, so there's nothing to guess and a slow hash would only slow every MCP request. The database holds the hash, so a leaked table gives nothing that works.
3. **"Why an advisory lock for the snippet cap, and why only snippets?"** (`src/lib/library-store.ts:57-68`, [0025](../adr/0025-serialize-snippet-creates-per-user-with-an-advisory-lock.md)) Twenty parallel creates at 45 ended at 61 because every one counted 45. A transaction-scoped lock keyed on the user serializes that user's creates and releases itself on commit, so a pooled connection never keeps it. Folders and tokens have the same race; the ADR says so and leaves them for later because nothing creates them in parallel today.
4. **"How does the theme arrive with no flash, and what did it cost?"** (`src/app/layout.tsx:70-77`, `src/lib/theme.ts`, [0029](../adr/0029-remember-the-theme-in-a-cookie-and-highlight-code-in-both.md)) The toggle writes a cookie in the browser, and the root layout reads it on the server and sets `data-theme` on `<html>`, so the first frame is already in the right theme. The cost is that reading a cookie makes every route dynamic, which was already true because every page checks the session.
5. **"How can one Shiki pass serve two themes?"** (`src/lib/highlight.ts:16-24`, `src/app/globals.css:198-203`) Shiki's multi-theme mode writes the default theme's color inline and each other theme's as a CSS variable on the same span. One rule under `[data-theme="8bit"]` switches every span to that variable, so switching themes is a CSS change and nothing is re-highlighted.
6. **"Why does `bg-gray-800` do nothing here?"** (`src/app/globals.css:119-122`, [0027](../adr/0027-one-default-identity-and-an-8-bit-theme-on-semantic-tokens.md), `src/lib/theme-tokens.test.ts`) Tailwind's palette is reset to nothing and every color utility is a token read at runtime, so components can only name a role like `surface` or `fg-muted` and a theme only has to override variables. A test fails the build if a palette class gets in, and another checks every text pairing against WCAG AA in both themes.
7. **"What stops a snippet from steering the search?"** (`src/lib/ai-search.ts:28-44`, [0005](../adr/0005-ai-features-as-synchronous-claude-calls.md) line 35, [0024](../adr/0024-remote-mcp-server-with-personal-access-tokens.md) line 62) Nothing, on purpose: titles and descriptions go straight into the prompt, and the worst case is a user skewing their own results. The ADRs say that stops being acceptable the moment snippets come from other people, which is why public sharing is in Not planned.

Clever without an explanation: the nested `startTransition` (question 3 from the last audit) is still the only one. Everything new this round, the lock's hash function, thinking turned off on Haiku, the cookie rule that mirrors next-auth, has its reason next to it.

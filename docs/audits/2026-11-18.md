## Findings

Ranked by how much each matters to "an engineer clicks the link and reads the code."

1. **`ARCHITECTURE.md` says "Last reviewed: 2026-11-08 (after ADR 0041)"** (`docs/ARCHITECTURE.md:5`). The body below it describes ADR 0067, so a reader sees a stale date on text that is actually current. This is the same finding as [2026-10-23](./2026-10-23.md) #4, back again. A stale roadmap line belongs in the same commit: `docs/ROADMAP.md:316` says the README screenshots "still show the old sidebar until `e2e/readme-images.ts` runs again". They were retaken in `68a654a`, four minutes after the icon rail landed (`3d4f266`). Small. Not 1.3's code, so it doesn't hold the tag by the rule, but it's one line next to finding 2.
2. **The "Recently deleted" heading splits the data model list** (`docs/ARCHITECTURE.md:209`). `### Recently deleted` sits in the middle of the bulleted list under "Data model". So the bullets at lines 223-230 now render under "Recently deleted": `ApiToken`, `DemoStart`, `User.email`, the NextAuth tables, `Session`, foreign key indexes, row-level security, and migrations. The fix is to move the subsection after the list. Small. New, in 1.3's docs.
3. **Comments still say "not archived" where the code also leaves out deleted snippets.** See `src/app/api/mcp/route.ts` ("AI search reads only snippets that aren't archived"), `src/app/api/snippets/search/route.ts` ("Not the archive"), and `src/lib/ai-search.ts:17,19`. The code is right, since `listActive` filters both (`src/lib/library-store.ts:73-77`). The comments went stale when 1.3 landed. Small. New.
4. **The double `startTransition` still has no "why", and it has spread.** A *transition* is React's way to mark an update as "can wait", which gives you a pending flag such as "Deleting..." until it lands. The pattern is in `src/components/SnippetFormModal.tsx:88`, `useDeleteSnippet.ts:57`, `useArchiveSnippet.ts:39`, `useRestoreSnippet.ts:37` (new in 1.3), and `DashboardClient.tsx:283`. Each comment says what happens ("land in the same render"). None says why a second wrap is needed. React only treats state updates made *before* the first `await` inside an async transition as part of it. Without the second wrap, `router.refresh()` and the close would run as ordinary updates, and the pending label would drop before the refreshed list arrived. Small: one comment in one place that the others point to. Still open since [2026-10-23](./2026-10-23.md).
5. **The sidebar doesn't tell a screen reader which row is open.** `src/components/FolderSidebar.tsx` marks the selected row only with a CSS class (`ROW_SELECTED`). There is no `aria-current` anywhere in the file. `aria-current="page"` is the attribute that makes a screen reader say "current" on a link or button. Pick All snippets, which has no heading above the cards, and nothing announces where you are. That includes the new Recently deleted row (`FolderSidebar.tsx:561`) and its rail button (`FolderSidebar.tsx:441`). From reading the code. Small. New.

**Worth knowing, no fix needed:**

- **The trash limit is soft under parallel deletes** (`src/lib/library-store.ts:99-118`). Each delete trims Recently deleted to its limit inside its own transaction. Two deletes at once can't see each other's uncommitted row, so each trims from its own view, and the trash can end up one over per extra parallel delete until the next delete trims it. That's bounded, and not worth a lock.
- **Rolling back to 1.2.1 would bring deleted snippets back into the library.** The old code doesn't read `deletedAt`. Vercel's Instant Rollback (one click to serve an older build) would show every deleted snippet in the library and count it toward the cap, and the old `DELETE` would remove rows for good. The add-first rule ([0016](../adr/0016-apply-migrations-in-the-production-build.md)) protects deploys going forward, not rollbacks.
- **The dashboard can now highlight up to 100 cards per load** (`src/app/dashboard/page.tsx:49`): 50 in the library plus 50 in Recently deleted, each highlighted on the server by Shiki. Fine at this size.
- **The dashboard's snippet query is its own copy** (`src/app/dashboard/page.tsx:30-38`), not a store method. So its "an expired snippet can't show even if the purge missed it" clause isn't covered by `test:db`. The purge it repeats is covered.
- **Carried over:** three GET routes nothing in the interface calls (`/api/snippets`, `/api/folders`, `/api/tokens`). `lib` imports a type from `components` (`src/lib/demo.ts:10`, `src/lib/landing-samples.ts:1`). A create waiting on the advisory lock holds a pooled connection (Parked).

## Can Ryan answer for it?

Since the last audit: 121 commits (64 `docs:`, 22 `feat:`, 18 `fix:`, 10 `chore:`, 5 `test:`, 2 `style:`). Commits after 2026-11-12 don't carry a co-author line ([0054](../adr/0054-credit-claude-in-the-readme-not-on-every-commit.md)), and Claude worked on all of them.

1. **"How does the trash empty without a cron job?"** (`src/app/dashboard/page.tsx:23-27`, `src/lib/library-store.ts:131-136`, [0067](../adr/0067-recently-deleted-a-30-day-trash-emptied-when-the-library-loads.md)) When you load your dashboard, it first deletes your own snippets that were deleted over 30 days ago. A scheduled job would have needed a handler with no signed-in user and one query across everyone, so a bug could only ever hit one person's rows this way.
2. **"If deleted snippets don't count toward the cap, what stops unlimited rows?"** (`src/lib/library-store.ts:99-118`, `src/lib/snippets.ts:229-247`) Recently deleted holds as many as the library, and the delete that goes over the limit purges the oldest in the same transaction. A restore takes the same per-user lock as a create, so a restore and a create at 49 can't both get in.
3. **"Why plain SHA-256 for session tokens and not bcrypt?"** (`src/lib/session-tokens.ts:28-30`, [0061](../adr/0061-store-session-tokens-as-their-sha-256.md)) A slow hash protects guessable things like passwords, and a session token is 32 random bytes, so there's nothing to guess. A fast hash keeps every request to one indexed lookup.
4. **"What stops the demo running up your AI bill?"** (`checkAiLimits` in `src/lib/rate-limit.ts`, [0046](../adr/0046-a-shared-daily-ceiling-on-demo-ai-calls.md), [0047](../adr/0047-give-each-address-a-share-of-the-demo-ai-ceiling.md)) Each guest gets 10 calls an hour, each address 100 a day, and all guests together 500 a day, which caps it at about $0.50. They're checked narrowest first, so someone past their own limit can't drain the shared one.
5. **"How do you stop one user touching another's snippets?"** (`src/lib/snippets.ts:121-124`, `src/lib/library-store.ts:92-95`, [0018](../adr/0018-route-handler-logic-in-lib-with-a-store.md)) Every handler checks the owner first and answers `403` for both missing and someone else's, and every write also puts `userId` in its `where`. It's tested against an in-memory store with two users and against Postgres.
6. **"Why call `startTransition` twice?"** (`src/components/useDeleteSnippet.ts:45-61`) React only counts updates before the first `await` as part of a transition. The refresh after the API call needs wrapping again, or "Deleting..." would vanish before the card did.
7. **"How do schema changes avoid breaking the live site?"** ([0016](../adr/0016-apply-migrations-in-the-production-build.md), [0038](../adr/0038-push-commits-with-a-migration-to-a-branch-first.md)) Migrations only add things and run before the build, while the old code keeps serving. They go to a branch first so CI checks them before they can touch production. The catch, from "Worth knowing" above: a rollback isn't covered.

Clever without an explanation: the double `startTransition` is still the only one. The ADRs are thorough enough to learn from.

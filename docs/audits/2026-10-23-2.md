## Findings

Ranked by how much each matters to "an engineer clicks the link and reads the code."

1. **Keyboard users can't open a card, and screen readers are told something false.** Each card gets dnd-kit's `role="button"`, `tabIndex=0`, and its default description, "To pick up a draggable item, press the space bar" (`node_modules/@dnd-kit/core/dist/core.esm.js:41`). Only `PointerSensor` is registered (`src/components/DashboardClient.tsx:76-80`) and the card only has `onClick` (`src/components/SnippetCard.tsx:80`). Tab to a card and press Enter or Space: nothing. Edit, Copy, and Delete still work from the keyboard; the preview doesn't. The end-to-end test opens the preview by clicking (`e2e/demo.spec.ts:49`). The README points at the accessibility checks (`README.md:94`), so a reviewer who presses Tab finds this fast. Small: an `onKeyDown` that opens the preview on Enter, and `accessibility.screenReaderInstructions` on `DndContext` that describe what works. Partly on the roadmap: keyboard drag and drop and card roles are Parked (`docs/ROADMAP.md:141,143`), but neither mentions the unreachable preview or the false instruction.
2. **The folder `⋯` button vanishes when it has keyboard focus.** It's `opacity-0` unless hovered or on a touch screen (`src/components/FolderSidebar.tsx:333`), with no `focus-visible:opacity-100`. Tab through the sidebar and focus disappears on every folder. Small. New.
3. **`preview.png` is taken and committed, but nothing uses it.** `e2e/readme-images.ts:60` shoots it; the README never shows it. 214 KB per regeneration, on top of the cost ADR 0032 already accepts. Small: use it or drop the shot. New.
4. **One stale Parked line.** `docs/ROADMAP.md:141` says the `⋯` button "has no label." It has had one since Phase 5 (`src/components/FolderSidebar.tsx:329`). Small. New.
5. **Worth knowing, no fix needed.** All carried over: a create waiting on the lock holds a pooled connection (`src/lib/create-lock.ts:25-29`); three GET routes nothing calls; the dashboard's queries repeat the stores' (`src/app/dashboard/page.tsx:19-31`); `lib` imports a type from `components` (`src/lib/demo.ts:9`, `src/lib/landing-samples.ts:1`); MCP's `1.0.0` against `package.json`'s `0.1.0`; `unstable_retry` in `src/app/error.tsx:18`.

Since the last audit: 10 commits, all co-authored with Claude (7 `docs:`, 1 `feat:`, 1 `fix:`, 1 `chore:`). Whole history: 203 of 235 co-authored.

1. **"How do you stop one user reading or changing another's snippets?"** (`src/lib/snippets.ts:81-84,157-165`, `src/lib/library-store.ts:62-70`, [0018](../adr/0018-route-handler-logic-in-lib-with-a-store.md)) Every handler resolves the user first (401) and checks the record's owner before touching it (403, the same for missing and someone else's), and the writes put `userId` in the `where` clause too, so a skipped check still can't change another user's row. That's tested against an in-memory store with two users and against a real Postgres.
2. **"How does AI search work, and why not embeddings?"** (`src/lib/ai-search.ts:28-70`, [0005](../adr/0005-ai-features-as-synchronous-claude-calls.md), [0023](../adr/0023-one-ai-module-on-claude-haiku.md)) Claude gets the query and a numbered list of each snippet's title, language, tags, and description, and answers with the matching numbers, which are parsed defensively and mapped back. With a 50-snippet cap the whole library fits in one cheap Haiku prompt, so embeddings would add a provider and pgvector without paying for themselves yet.
3. **"What stops a script getting past the 50-snippet cap with parallel requests?"** (`src/lib/create-lock.ts:20-30`, [0025](../adr/0025-serialize-snippet-creates-per-user-with-an-advisory-lock.md)) The count and the insert run in one transaction that first takes a Postgres advisory lock on the user and the kind of create. A second create waits, then counts the first one's row, and a database test fires 20 at once to prove it.
4. **"How does an MCP client sign in, and why tokens instead of OAuth?"** (`src/lib/api-tokens.ts:56-88`, `src/lib/mcp.ts:36-55`, [0024](../adr/0024-remote-mcp-server-with-personal-access-tokens.md)) A token is `snippr_` plus 32 random bytes, shown once, and only its SHA-256 is stored, which is enough because a long random token has nothing to guess; each tool calls the same `lib` function as the matching endpoint. OAuth means running an authorization server, and tokens already cover Claude Code and Cursor.
5. **"How does the demo work without signing in, and what stops abuse?"** (`src/lib/demo.ts:84-116`, `src/lib/guest.ts:43-66`, [0012](../adr/0012-demo-mode-as-expiring-guest-users.md)) It creates a real user with an expiry, a seeded library, and a session row, sets the cookie NextAuth would, and an adapter wrapper treats an expired guest's session as none. Abuse is bounded by 5 demos an hour per hashed IP, 10 snippets, and 10 AI calls per guest, and expired guests are deleted when the next demo starts.
6. **"How do you keep a schema change and the code that needs it from deploying out of order?"** (`scripts/deploy-migrations.mjs`, `scripts/migrate-gate.mjs`, [0016](../adr/0016-apply-migrations-in-the-production-build.md), [0020](../adr/0020-ci-on-github-actions-gating-production-deploys.md)) Production builds run `prisma migrate deploy` before `next build`, and Vercel holds the deploy until CI passes, including migrations on an empty Postgres. Migrations add first and remove in a later push, so the code already live keeps working.
